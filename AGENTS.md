# AGENTS.md

## Repository shape
Seven independent projects with **zero shared C++ source**; the stdin/stdout player feed in `docs/protocol.md` (**v2**) is their only contract. Change it whenever messages change.

- `lyrics-app/` — standalone Qt6 desktop-lyrics display (port of lx-music-desktop's `renderer-lyric`). Owns ALL lyric acquisition (sidecar `.lrc` + embedded tags via TagLib, encoding conversion via ICU), parsing (LRC, lxlrc, tlrc/rlrc, the `[awlrc:…]` container), line selection (including karaoke word-tag parsing that drives line timing), line-by-line rendering (word tags are stripped; no per-word fill), and settings. The app is host-agnostic; it does not know Fooyin exists.
- `plugins/fooyin/` — Fooyin (>= 0.11.1) adapter. Playing context + transport only — watches playback events, samples the analyser, spawns `lx-lyrics-app --player-feed` as its **direct child**, and pushes `set_*` JSON lines; never acquires lyrics, parses LRC, or renders anything.
- `plugins/deadbeef/` — DeaDBeeF C adapter (`ddb_lxlyrics.so`); same feed contract, pure POSIX C feed thread, declared API floor **1.16** (deadbeef >= 1.9.3).
- `plugins/rhythmbox/` — Rhythmbox libpeas Python adapter; spawns the app via `Gio.Subprocess`; no analyser API (`spectrum: false`). `lxlyrics.plugin` declares **no** `Depends=rb` (the adapter imports nothing from Rhythmbox's shared `rb` plugin; the `RB` typelib is librhythmbox-core), so a `Dependency “Shared plugin code” failed to load` error means the libpeas **python3 loader** is missing from the environment (Arch builds libpeas with `-D python3=false`) — never a defect to "fix" in the adapter; its README carries the rootless provisioning recipe.
- `plugins/audacious/` — Audacious general plugin (`lxlyrics.so`, floor **4.6.1**): pure POSIX C transport + C++17 glue, the same direct-child feed. No menu item and no per-user plugin dir — the host's Plugins page is the toggle — but `PluginInfo` carries a declarative `PluginPreferences` (a label + one `WidgetString` entry) that both the Qt and GTK frontends render as the row's settings page for the app path; the plugin installs into `<prefix>/lib/audacious/General/`. `spectrum: true` via the public `Visualizer` API; config key `[lx-lyrics] app_path` in `$XDG_CONFIG_HOME/audacious/config`.
- `plugins/quodlibet/` — Quod Libet event plugin (floor **4.4.0**, single Python module `lxlyrics.py`): `Gio.Subprocess` child driven from Quod Libet's GLib main loop, same feed. No analyser API (`spectrum: false`), but a queryable fullscreen state (`set_fullscreen`); self-disables through the plugin manager on `close_requested`; config option `plugins/lxlyrics_app_path` in `$XDG_CONFIG_HOME/quodlibet/config`.
- `plugins/vlc/` — VLC 3.0.x interface module (`liblxlyrics_plugin.so`) loaded via `--extraintf=lxlyrics`, same feed. Poll-based 500 ms sampler + VLC-free `mapper.c`, `spectrum: false`; VLC 4 is unsupported; config keys `lxlyrics-enabled` / `lxlyrics-app-path`.
- `references/` — gitignored, read-only copy of lx-music-desktop 2.12.2 source. The parity reference: keep `desktopLyric.*` key names and lx-music semantics verbatim. Never edit.
- `docs/` — `architecture.md` (design), `protocol.md` (the shared contract, v2), `research/` (engineering research notes).

Dropped players: Strawberry, Clementine, Elisa and Tauon have **no extension mechanism** — dropped per decision (no MPRIS fallback, no forks). Audacious, Quod Libet and VLC adapters live under `plugins/` above.

## Build & verify (no CI)
```sh
cd lyrics-app && cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug && cmake --build build
ctest --test-dir build                 # 6 suites: engine(44) lyricplayer(33) feed(33) config(8) renderer(21) controller(32) — 171 slots
ctest --test-dir build -R engine       # single suite
QT_QPA_PLATFORM=offscreen timeout 3 ./build/lx-lyrics-app --demo # expect exit code 124 (timeout kill = no crash)
printf '{"v":2,"action":"nonsense"}\n' | QT_QPA_PLATFORM=offscreen ./build/lx-lyrics-app --player-feed; echo "exit=$?" # expect exit=1 and a protocol-error log line
```
- The headless demo check MUST set `QT_QPA_PLATFORM=offscreen`: `main.cpp` forces `xcb`, so on a box with no display server a bare `env -u DISPLAY … --demo` aborts (exit 134, Qt xcb "could not connect to display"). Use `xvfb-run -a … --demo` when the check must run on the user's real platform (xcb).
- `./tools/lint.sh [--fix] [--format-only] [--tidy-only]` is the style/static-analysis gate, and it is **C++-only**: clang-format over `lyrics-app/src`, `lyrics-app/tests` and `plugins/fooyin/src` (`.cpp`/`.h`), plus clang-tidy via `run-clang-tidy` over the `lyrics-app` and `plugins/fooyin` build dirs (it strips Qt's GCC-only `-mno-direct-extern-access`, which the clang driver behind clang-tidy otherwise rejects). Findings fail the run. `plugins/deadbeef/` (C), `plugins/rhythmbox/` (Python), `plugins/audacious/` (C/C++), `plugins/quodlibet/` (Python) and `plugins/vlc/` (C) are **outside this gate**: keep the C/C++ sources clang-format-clean under the repo `.clang-format` by hand (they pass `clang-format --dry-run -Werror` today); the Python adapters have no style gate — their hermetic unittest suites are their check.
- Suites are separate binaries built from the subset of sources each exercises: `build/lyrics-app-tests` (engine), `lyrics-app-lyricplayer-tests`, `-feed-`, `-config-`, `-renderer-`, `-controller-`; run one directly to bypass ctest. The `feed` suite compiles the app's `FeedReader` AND the plugin's Fooyin-free `plugins/fooyin/src/feedwriter.cpp` — both halves of the wire contract.
- `tests/testbootstrap.h` pins `QT_QPA_PLATFORM=offscreen` for the widget suites (renderer, controller) by odr-using `kForceOffscreen`; they must keep passing with no display server (`env -u DISPLAY -u WAYLAND_DISPLAY XDG_RUNTIME_DIR=$(mktemp -d)` is the check).
- App run modes: `--player-feed` (host-driven — an adapter spawns the app as its direct child; EOF on stdin quits immediately), `--demo` (self-fed — fake track AND a synthetic spectrum transport, so the visualizer renders with no host), no flag = inert window. `--ws`/`--exit-on-disconnect` no longer exist.
- plugins/fooyin needs Fooyin built with `INSTALL_HEADERS=ON`; artifact `build/fyplugin_lxlyrics.so`, installed to Fooyin's `<prefix>/lib/fooyin/plugins` (`tools/install.sh` uses the per-user `~/.local/lib/fooyin/plugins` unless `--fooyin-plugin-dir` says otherwise). It has **no test suite of its own** — the app's `feed` suite compiles its Fooyin-free `feedwriter.cpp` as the host half of the wire.
- plugins/deadbeef's configure step **requires** DeaDBeeF headers (a distro SDK — `deadbeef/deadbeef.h` under a standard prefix, found by CMake's `find_path` unaided — or a 1.10.1 checkout via `-DDEADBEEF_INCLUDE_DIR=…`; a bare `cmake -B build -G Ninja` FATAL_ERRORs only when no header is found) because the plugin compiles against them — the `feed_test` target is the header-free part (it builds only `feed.c` + `json.c`), so `ctest --test-dir build` runs with no DeaDBeeF installed. Install `ddb_lxlyrics.so` to `~/.local/lib/deadbeef/`, then restart the player. API floor 1.16 (deadbeef >= 1.9.3) — see its README for the upstream header proof.
- plugins/rhythmbox installs by copying its directory to `~/.local/share/rhythmbox/plugins/lxlyrics/`; tests run hermetically with `python3 -m unittest discover -s plugins/rhythmbox/tests -v` (39 tests); PyGObject/girepository notes in its README.
- plugins/audacious builds with `cd plugins/audacious && cmake -B build -G Ninja && cmake --build build` (artifact `build/lxlyrics.so`). The configure step **requires** the Audacious headers — `pkg-config audacious` (its `audacious_include_dir`), or `-DAUDACIOUS_INCLUDE_DIR=<prefix>/include` — and FATAL_ERRORs without them; the `feed_test` target builds only `feed.c` + `json.c`, so `ctest --test-dir build` (1 hermetic suite) runs with no Audacious player — the headers were needed only at configure time. Install `build/lxlyrics.so` to `<prefix>/lib/audacious/General/` and restart Audacious.
- plugins/quodlibet has no build step: copy the module to `~/.config/quodlibet/plugins/lxlyrics.py`. Tests run hermetically with `python3 -m unittest discover -s plugins/quodlibet/tests -v` (56 tests) — no Quod Libet, GTK, PyGObject, display server or app binary needed.
- plugins/vlc builds with `cd plugins/vlc && cmake -B build -G Ninja && cmake --build build` (artifact `build/liblxlyrics_plugin.so`). The VLC module headers are a hard configure-time requirement — `pkg-config vlc-plugin`, or `-DVLC_INCLUDE_DIR=/path/to/vlc/include` — while the two test targets (`feed_test`, `mapper_test`) never see a VLC header, so `ctest --test-dir build` (2 hermetic suites) runs with no VLC installed. Install into a directory on `VLC_PLUGIN_PATH` (or `<libdir>/vlc/plugins/`) and restart VLC with `--extraintf=lxlyrics`.
- `build/` dirs are gitignored and shared across tasks; a concurrent LSP reconfiguration can transiently remove outputs — rebuild once before diagnosing.
- The LSP diagnostic "tst_config.moc not found" is pre-existing (AUTOMOC generates it at build time); ignore it.
- Always rebuild after any code modification — never report a change as done until `cmake --build build` succeeds.

## lyrics-app layout
`src/` is layered as: `engine/` (LRC/word parsers, `LyricPlayer` timed engine, `LyricSelector` lxlrc-vs-lrc choice + extended lyrics), `renderer/` (`LyricRenderer` widget, `ControlBar`, `SpectrumWidget`), `host/` (`FeedReader` v2 stdin/stdout protocol, `TrackLyrics` acquisition, `PipeIO` pipe devices), `bridge/` (pause-hide), `app/` (controller, spectrum bridge + transport, CLI options), plus `config/`, `settings/`, `window/`, `i18n/`. Tests live in `tests/` as six QTest binaries.

## App quirks
- `main.cpp` forces `QT_QPA_PLATFORM=xcb` before QApplication unless the env var is already set — client-side `move()`/position restore only works under X11. Set `QT_QPA_PLATFORM` beforehand to override. Always-on-top/click-through remain compositor best-effort on Wayland (KDE window rules: `tools/lx-lyrics.kwinrule`).
- `main.cpp` also forces `QT_FORCE_STDERR_LOGGING=1` unless set: Qt >= 6.11 silences `qInfo`/`qWarning` when stderr is a pipe — and the feed's stderr IS a pipe by design. Respect an explicit override.
- The app ignores `SIGPIPE` (`main.cpp`, and again in `host/pipeio.cpp` so the class is safe without a `main`) and writes its **stdout** non-blocking with a bounded budget: a host that stops draining (or closes) the app's stdout gets **one** `qWarning` and every later app→host line is dropped — the app keeps running, because **stdin EOF is the only quit trigger** (a dead stdout must never end a session).
- Config persists to `~/.config/lx-lyrics/config.json` (37 keys, writes debounced 500 ms). Defaults are **user-tuned**, deviating from `references/src/common/defaultSetting.ts` on 8 keys: enable, isAlwaysOnTop, isAlwaysOnTopLoop, fullscreenHide, width(300), fontSize(14), opacity(100), isZoomActiveLrc(true); x/y default null = auto-position. They live ONLY in `DesktopLyricConfig::loadDefaults()` — keep `lyricrenderer.h` member initializers and the config tests in sync.
- When locked the window is transparent and click-through and the ControlBar is hidden — `Ctrl+,` reopens the settings dialog (documented escape hatch).

## Plugin quirks
- `PlayerBridge` (playback events → `set_*` lines with `path` + metadata + state), `SpectrumSource` (analyser → 128 log-scaled bytes), `FeedWriter` (spawns `lx-lyrics-app --player-feed` as a direct child; writes the `hello` handshake and all host→app lines; strict-parses the two app→host actions; forwards the child's stderr). The app owns acquisition — the plugin has no lyric source, no socket server, and no detached spawn.
- `feedwriter.cpp` must stay **Fooyin-header-free**: the app's `feed` suite compiles it as the host side of the wire.
- `lxlyrics.json.in` must keep **top-level capitalized keys** (`Name/Version/Category/...`, `Version` via `@PROJECT_VERSION@`). Wrapping them in an IID/MetaData/className object broke plugin discovery in Fooyin.
- FooyinConfig does NOT propagate Qt modules (only Core/Widgets/Sql/Concurrent/Network) — the plugin declares its Qt6 Core/Widgets dependency in `plugins/fooyin/CMakeLists.txt`. ICU/WebSockets are no longer needed on the plugin side.
- `plugins/deadbeef/`: `lxlyrics.enabled` **is** the toggle state (DeaDBeeF's action API has no checkable flag, so the menu item carries no tick) and it is honoured at player start (`DB_EV_PLUGINSLOADED` → `restore_session()`, which clears the key if the session cannot start). The host's panel is a layout string (`lxlyrics_config_dialog`: `lxlyrics.app_path` entry + `lxlyrics.enabled` checkbox) that gtkui renders into Preferences → Plugins → LX Lyrics — the string IS the dialog, no GTK is linked; `DB_EV_CONFIGCHANGED` mirrors only `enabled` onto the live session (key on + no session → start, a start that cannot spawn clears the key; key off + session → end) and deliberately ignores `app_path`, which every keystroke rewrites and the next `start_session()` reads. The reader parses app→host lines strictly — a wrong `v`, an unknown action, a malformed payload or an over-1 MiB line is a protocol error that ends the session, while a line that is not a JSON object is skipped loudly. The write end is `O_NONBLOCK` with a bounded `poll()` wait, and the feed object is reference-counted because `message()` runs on DeaDBeeF's player thread while the menu action runs on the GTK main thread.
- `plugins/rhythmbox/`: the child's stdin is made non-blocking (`os.set_blocking`) so an app that stops draining cannot park Rhythmbox's main loop, and the pending queue is capped at `MAX_PENDING_LINES` — the oldest stale lines are dropped with one log per overflow episode, never the in-flight line or the leading `hello`. A well-formed line with a wrong `v` or an unknown action is a protocol error (§7): log, kill the child, uncheck the toggle. `stop()` closes the child's stdin and escalates to `force_exit()` only after `STOP_GRACE_MS`.
- `plugins/audacious/`: API version **49** pins the floor to Audacious ≥ 4.6.1 — the loader rejects anything outside the window it was compiled against, so **one binary cannot serve both 4.6 (48) and 4.6.1**. There is no per-user plugin dir: the `.so` goes to `<prefix>/lib/audacious/General/` and Audacious must be restarted to dlopen it. The plugin adds no menu item — the host's Plugins page *is* the toggle — but `info.prefs` (a `const PreferencesWidget[]` in a `PluginPreferences`) gives it the row's settings page, the app path only, offered only while the plugin is enabled (`aud_plugin_has_configure()` is literally `(bool)info.prefs`). Every `aud_*` host call happens on the main thread (hook handlers + a `TimerRate::Hz4` 250 ms timer refresh a mutex-guarded snapshot) because `aud_drct_*` is documented not thread-safe; the feed's reader thread only reads that snapshot. Registering a `Visualizer` also switches the host's vis runner on for the whole session (frames arrive from its 30 Hz timer), and `set_fullscreen` is omitted — libaudcore exposes no queryable fullscreen state.
- `plugins/quodlibet/`: copy the **single module**, not the directory — Quod Libet's scanner walks subdirectories and would try to import `tests/test_lxlyrics.py` as a plugin; there is no `.plugin` metadata file (class attributes carry the metadata). The plugin manager's toggle is the only way to start a session (an event plugin has no menu); its `PluginPreferences` pane (the app-path entry, under its description) is the Plugins window's right-hand side when the LX Lyrics row is selected, reachable whether or not the plugin is enabled. `close_requested` turns the plugin off through the same `PluginManager.enable(..., False)` + `save()` calls the Plugins window's toggle makes, so nothing respawns. Everything runs on the GTK main loop: one armed async line read at a time, non-blocking child stdin, queued lines capped at `MAX_PENDING_LINES` (64) with oldest-stale drops, and a `STOP_GRACE_MS` grace before `force_exit()`.
- `plugins/vlc/`: VLC only scans `lib*_plugin.so` and derives `MODULE_STRING` from the file name — that string is what `--extraintf=` matches, so both are pinned to `lxlyrics` and the module must be named `liblxlyrics_plugin.so`. `extraintf` is read once at libvlc start, so there is **no in-process re-enable** — restart VLC. The module descriptor is the module's whole GUI surface: `set_description()` labels its checkbox under Interface → Main interfaces → "Extra interface modules" (the control that loads it), `set_shortname()` labels the settings-tree node, and `set_help()` is the only place inside VLC that can spell out the enable+restart path — VLC's Simple settings pages bind literal option names, so an out-of-tree module can only appear under "Show settings: All". `lxlyrics-enabled` is **kept when VLC itself shuts down** (a restart restores it) but cleared when a session ends (user close, protocol error, the app exiting, failed spawn). Signal-mask trap: `vlc_clone()` blocks `SIGHUP`/`SIGINT`/`SIGQUIT`/`SIGTERM`/`SIGPIPE` around `pthread_create()`, the session thread inherits the mask, and a `fork()`+`execv()` would hand the app a blocked mask that survives `exec()` — so `feed.c` resets the child's mask to the empty set before `execv()` (and the test spawns from a thread carrying VLC's mask to keep it that way). The clock is a 500 ms poll of `pl_CurrentInput()` with no VLC pointer surviving a tick; the state/seek diffing is VLC-free in `mapper.c`.

## Test fixtures
`lyrics-app/tests/fixtures/sample.lrc` (UTF-8) and `sample-gbk.lrc` (same lyrics as GBK bytes) are the encoding-path e2e fixtures: `iconv -f GBK -t UTF-8 tests/fixtures/sample-gbk.lrc` must equal `sample.lrc` (the `feed` suite asserts exactly that). `embedded-lyrics.flac` carries `LYRICS=[00:00.00]Embedded line one\n[00:01.00]Embedded line two` for the embedded-tag path. Keep them in sync when touching the fixtures.

## Conventions
- License split is intentional: `lyrics-app/` Apache-2.0 (ported logic); all six adapters under `plugins/` (`fooyin/`, `deadbeef/`, `rhythmbox/`, `audacious/`, `quodlibet/`, `vlc/`) GPL-3.0-only (a repo decision the hosts permit — Fooyin is GPL-3.0; Rhythmbox, Quod Libet and VLC are GPL-2.0-or-later, whose "or later" clause allows a GPL-3.0 plugin; DeaDBeeF's plugin API header is zlib-licensed; Audacious' libaudcore is BSD-2-Clause). SPDX header at the top of every source file.
- `./tools/install.sh [--player NAME]... [--prefix DIR] [--no-autospawn]` builds the app (always, in Release) and any of the six adapters — `--player fooyin|deadbeef|rhythmbox|audacious|quodlibet|vlc|all`, repeatable — with no `--player` it installs every adapter whose player it detects (the player's binary on `$PATH`, or that player's config dir) and `--player all` forces all six. `--prefix` is the app's install prefix only (the app lands in `<prefix>/bin`, default `~/.local`) and each adapter goes to its own player's plugin directory, overridable per adapter with `--fooyin-plugin-dir`/`--audacious-plugin-dir`/`--vlc-plugin-dir`, then writes the adapter's config so it finds the binary without manual entry: fooyin.conf `[LxLyrics]` `AppPath`/`RememberState` (a stale `AutoSpawn=` line is deleted), DeaDBeeF `lxlyrics.app_path`, Rhythmbox `[lx-lyrics] app-path`, audacious config `[lx-lyrics] app_path`, Quod Libet module `lxlyrics_app_path` (edited through Quod Libet's own config library), vlcrc `[lxlyrics] lxlyrics-app-path` plus `[core] extraintf=lxlyrics` when the module lands in a directory VLC scans (a per-user `~/.local/lib/vlc/plugins` install needs `VLC_PLUGIN_PATH`, and the launch line is printed instead). Every config write is read back; the run is idempotent. `--no-autospawn` writes each player's start-off state (fooyin `RememberState=false`, DeaDBeeF `lxlyrics.enabled=0`, Rhythmbox `enabled=false`, `lxlyrics` dropped from Quod Libet's `active_plugins`, vlcrc `lxlyrics-enabled=0`; Audacious has no such state — its Plugins page enable toggle *is* the session switch). Audacious (no per-user plugin dir) and a system VLC plugin dir need root: the exact `sudo install` command is printed, the script exits 1, and the other requested adapters are still installed.
- The repo owner handles pushes (often with tags); do not push unless explicitly asked.
